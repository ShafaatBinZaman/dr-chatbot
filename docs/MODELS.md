# Model artifacts

Large binaries are kept out of Git. GitHub rejects any single file over 100 MB, and a
repository full of checkpoints becomes painful to clone.

## What was excluded

| File | Size | Why |
|---|---|---|
| `drchatbot-model/model.safetensors` | ~294 MB | Over GitHub's file limit |
| `drchatbot-model/checkpoint-6/model.safetensors` | ~294 MB | Intermediate checkpoint |
| `drchatbot-model/checkpoint-6/optimizer.pt` | ~587 MB | Training state only, not needed for inference |
| `.venv/`, `.venv311/` | ~2.5 GB | Virtual environments are rebuilt from `requirements.txt` |
| `app/build/`, `.dart_tool/` | ~880 MB | Flutter build output, regenerated by `flutter build` |

## What was kept

`ml/disease_classifier_rf_model.pkl` and `ml/disease_classifier_xgb_model.pkl` are a few
megabytes each, so they are committed directly.

## Getting the advice model

Pick one of these:

**Retrain it.** Everything needed is in the repo:

```bash
cd backend
python train_drchatbot.py
```

**Publish it to Hugging Face Hub** (recommended — free, built for model weights):

```bash
pip install huggingface_hub
huggingface-cli login
huggingface-cli upload <your-username>/drchatbot-flan-t5 ./drchatbot-model
```

Then load it in `app.py` with `from_pretrained("<your-username>/drchatbot-flan-t5")`.

**Attach it to a GitHub Release.** Release assets allow files up to 2 GB and do not
bloat the clone. Create a release in the GitHub UI and drag `model.safetensors`,
`config.json`, `tokenizer.json`, `tokenizer_config.json`, `special_tokens_map.json`, and
`spiece.model` onto it.

Whichever you choose, place the files under `backend/models/drchatbot-model/` locally —
that path is gitignored.

## A note on Git LFS

Git LFS can store large files, but the free tier gives 1 GB of storage and 1 GB of
bandwidth per month across your whole account. One clone of a 300 MB model burns a third
of the monthly bandwidth. For a course project, Releases or the Hugging Face Hub are the
better fit.
